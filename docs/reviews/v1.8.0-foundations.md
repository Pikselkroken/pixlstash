## A. Security review (chief-security-officer) — VERDICT: SATISFIED, no blockers

The entire centralised authz gate (`pixlstash/authz/`) is **new in this PR** — this
was the adversarial sign-off on the gate mechanism itself plus every declaration.

**Coverage — arithmetic, independently reproduced against the running app:**
- 216 routes mounted, **all 216 declared** in `ROUTE_POLICIES` (`undeclared=[]`, `dead=[]`).
- Registry = 217 (the extra is the conditionally-mounted `POST /api/v1/test-hooks/ws-event`, waived + asserted). `_CURRENT_ROUTE_ALLOWLIST = frozenset()` — burned to zero, so completeness is arithmetic, not judgement.
- `AUTHZ_GATE_ENFORCING = True`; boot-fails on undeclared/dead/PUBLIC-drift + CI backstop. The BOLA-by-omission class is closed by construction.

**Verification:** 163 authz/security tests pass (19 guardrail + 27 gate both-direction + 117 host-capability/scope/read-token), 0 failures. The 4 `resolved_inline` name-derived routes keep their live inline checks (set/character/project). Step-5 inline-check removals in `config.py` are correctly backed by gate declarations. WS is HTTP-gate-exempt by design (`authenticate_websocket` retained). Dependencies: only a forward `fastapi 0.135.1 → 0.138.0` bump (required floor); no new npm packages, no downgrades.

**Findings (all LOW, non-blocking — fix at leisure):**
1. `docs/backend_architecture.md §16.3.1` prose says host-shell tier "17 = 13 local + 4 loopback"; real count is **18 = 13 + 5** (registry/matrix correct; only the sentence is stale).
2. `pixlstash/authz/gate.py:22-27` module docstring still says "Report-only default (`AUTHZ_GATE_ENFORCING = False`)"; actual constant (`:144`) is **`True`**. Stale header contradicts shipped state.
3. `pixlstash/auth.py` `is_loopback_ip`/`is_local_ip` return `True` on an **unparseable** IP (TestClient convenience) — a fail-open default for the `LOOPBACK_OWNER_ONLY` tier. Pre-existing convention, only reachable via the documented reverse-proxy caveat and requires an already-authenticated owner; consider failing closed in production.

**Accepted (pre-existing, on record, not this PR's to fix):** the §16.3 single-owner host-capability tier (retighten before multi-user); `scope_aware=True` as an audit assertion enforced by handler filters; reverse-proxy `trusted_proxies`/XFF-stripping as operator responsibility.
