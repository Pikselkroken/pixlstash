Surface 1 · async imports (#459)

Two-phase import: unsafe upload → safe background

The shell mirrors the real app: SideBar.vue (brand row, Global/Projects/Folders tabs, list rows, section headers), Toolbar.vue (36px band, stats button with the shipped activity dot), and the StatsSidebar.vue panel docked on the right, open to its Tasks tab (the task manager). The dialog keeps ImageImporter.vue's two-bar anatomy. Phase A (uploading, unsafe): calm present-tense copy, amber upload bar, and exactly one action — Cancel. No close/minimize control exists; a beforeunload guard is the hard backstop (press "Try to refresh"). Transition: the moment the last byte lands, the guard drops and the dialog auto-hides on its own — the dialog animates out while the count chip flies into the stats-sidebar task manager in one continuous motion, landing as a new task row. The flight is the dismissal: "moved to background, tab is free". No button press. Phase B (safe): the dialog is gone; the import is now just another task row (mirroring the ComfyUI generation row above it) with a live progress bar counting server-side import; the toolbar activity dot and the Tasks-tab pulse are the app-wide "work is live" lights; refresh is harmless. Reduced motion: plain fade, the row appears without travel.

Surface 2 · Scrapheap (DAM 1.1)

Scrapheap — the existing view, with the general soft-delete treatment

This is not a new view: it is the existing Scrapheap, reached from the real sidebar Scrapheap row (shown in the stage above), wearing the DAM 1.1 soft-delete treatment. The grid is ImageGrid.vue verbatim: 4px gap, 4px tile padding, 1:1 tiles at radius 8, the shipped hover glow, and the shipped selection treatment (the info-blue overlay + checkmark — noted below as drift vs the --active-wash system, reproduced faithfully). The resting context (title, count, retention, "Empty scrapheap") sits in the real 36px toolbar band. New elements — days-remaining chips (--scrim-photo) and the confirm dialog — are fully tokenized.     Handoff §8 · open decisions

    Proposed defaults, with rationale

    Import dismissal — DECIDED: the dialog auto-hides at the safe transition; the flight is the dismissal
    Phase A has no close/minimize affordance at all — its only action is Cancel; the calm "keep this tab open" note plus the native beforeunload prompt are the soft and hard layers of the same message, so the user never has to read a warning to be protected. The moment staging completes, the guard drops and the dialog animates out on its own while the count chip flies into the stats-sidebar task manager in one continuous motion — the flight is "moved to background, tab is free". No manual dismiss exists or is needed. Still open: cancel-mid-staging semantics (abort vs. keep-partial) ui/ux flow
    Flight / minimize host → the TASK MANAGER in the stats sidebar (StatsSidebar.vue, Tasks tab) — DECIDED
    The import lands as a task row in the Tasks-tab task manager, a sibling of every other running job (the ComfyUI generation run, backend workers). It mirrors the determinate .tm-comfy-bar row: a primary progress bar counting server-side import down to done, a .tm-status-dot--running (primary, 1.4s pulse) and a live message. This unifies "my import" with the app's existing task model instead of inventing a second indicator: the toolbar tb-stats-activity dot and the .tm-tab-pulse on the Tasks tab are the shared app-wide "work is live" lights, and the toolbar stats button is what opens the panel. The two rejected alternatives — reviving SideBar.vue's orphaned .sidebar-brand-task-btn slot, or landing a badge on the toolbar dot — are not used: the first is a one-off indicator with no task detail; the second overloads the activity light with a count. Landing punctuation on the row reuses the §6 spring-pop + glow (--dur-4 / --ease-spring).
    Scrapheap restore/purge — DECIDED as the general treatment of the existing Scrapheap: floating selection pill + toolbar-resting "Empty scrapheap", all destructive behind a confirm
    This styles the existing Scrapheap (the shipped sidebar row and delete_scrapheap_selection flow), not a new view. Selection actions follow SelectionBar.vue's real pattern (floating bottom-centre pill); Restore carries the affirmative weight (primary icon), Delete forever is error and always confirmed; the resting context (count, retention, Empty scrapheap) lives in the real 36px toolbar band. Note: handoff §13 describes SelectionBar as a full-width --bar-height band; the shipped component is this floating pill — the doc should be reconciled to reality (or vice versa) before the bar-height migration.
    Delete forever = ACTUAL destruction, including reference-folder originals — DECIDED (reverses rev 3)
    "Delete forever" now genuinely destroys the file, with no softening in the copy. For a reference-folder picture (whose file_path is an absolute path to the user's original on disk), the confirm carries a strong, specific error-tinted warning that names the exact original file path being removed (e.g. /mnt/photos/iceland-2024/harbor_dusk.raw) — it is deleting the original photo, not just the library entry. Managed pictures get the standard permanent-delete copy.

    Backend behavior change (implementation note): delete_scrapheap_selection (pixlstash/routes/pictures/_crud.py) must os.remove even allow_delete_file=False items on an explicit delete-forever, and log file_removed=True. This deliberately overrides the routine reference-folder file protection (which today keeps the file and logs file_removed=False) because the user has explicitly chosen destruction. Recording file_removed=True keeps the restore ledger honest: file_removed=True means the content is genuinely gone, so restore correctly drops the row rather than resurrecting a still-alive file. (The routine reference-folder scan / soft-delete path is unchanged — only the explicit delete-forever action escalates to physical removal.)
    Retention window shown as 30 days product / flow — veto welcome
    Surfaced in the toolbar meta, per-tile days-remaining chips (--scrim-photo, matching the shipped bottom-left badge convention), and the empty-state copy, aligned with the file_removed retention semantics of the missing-file purge. The visual treatment holds for any window; the number is the maintainer's call.
    New-dialog surface: standard surface dialog, not the shipped dark-surface modal veto welcome
    Handoff §7 specifies the standard dialog look for the non-blocking import; ImageImporter.vue's current full-screen dark-surface modal reads as "the app is busy" — exactly the impression #459 removes. Phase colours replace the shipped unnamed gradients: amber accent = attention (upload), olive primary = safe (server import).
